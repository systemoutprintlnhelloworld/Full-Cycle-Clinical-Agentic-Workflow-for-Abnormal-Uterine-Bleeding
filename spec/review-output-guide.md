# 审阅输出指南（精简版）

目标：让你能**在 Excel 里直接看懂**每个指标“分子/分母从哪来”，并知道**哪里需要你人工复核**以及如何反馈。

## 1) 你应该打开哪些文件？

| 你要看什么 | 文件 |
|---|---|
| 汇总入口（最先看） | `outputs/latest/summary/总览.xlsx` |
| 中心×模型指标汇总（CSV） | `outputs/latest/summary/指标汇总_中心模型.csv` |
| 解析/表头异常（中文解释） | `outputs/latest/summary/解析异常.csv` |
| 每个中心×模型的“审阅表”（核心） | `outputs/latest/<中心>/<模型>/审阅表.xlsx` |
| LLM 指标试跑结果（若已运行） | `outputs/latest/summary/llm_results_<裁判模型>__<渠道>.xlsx` |
| 状态修正副本与审计（不改 data/） | `work/latest/fixed_excels/`、`work/latest/status_audit/status_diff.csv` |

> 原则：`data/` 与 `docs/` **只读不改**。所有修正/审计只会写到 `work/latest` 与 `outputs/latest`。

## 2) `审阅表.xlsx` 里每个 Sheet 是干什么的？

| Sheet | 用途 | 你需要看什么 |
|---|---|---|
| `1_汇总(中心-模型)` | 单行汇总 | 快速看：D1/D2 检查匹配率、无效循环率、Gate/各阶段评分均值 |
| `2_病例-流程状态` | 状态一致性核对 | 是否存在“终止于XXX”后仍显示未经过但没标注原因等（若有会出现在 `6_需要复核-状态逻辑`） |
| `2_病例-检查匹配` | **检查匹配率(严格)** 的分子/分母（按病例） | 直接看每个病例的分子/分母与匹配率（可手算） |
| `2_病例-无效循环` | **无效循环率(0匹配)** 的分子/分母（按病例） | 直接看每个病例的 0匹配轮次/总轮次 与无效循环率 |
| `3_病例-裁判评分` | Gate 与 D3/D4 裁判分数（按病例） | 你关心的各分项是否都在、是否缺失 |
| `4_检查-轮次明细` | **逐轮 source data**（最关键的可追溯表） | 每轮：AI请求数、匹配数、未匹配数、来源、判官列表等 |
| `4_无效循环-逐轮明细` | 无效循环率(0匹配) 的逐轮明细 | 只保留循环阶段(D1/D2 Loop)且有请求的轮次：可直接手算分子/分母，并区分“未评测(裁判缺失)” |
| `5_需要复核-检查匹配` | 仅包含“可能算错/可疑”的轮次 | 看 `复核原因(为何入表)`，必要时在“你的反馈”列填写意见 |
| `6_需要复核-状态逻辑` | 状态推断的逻辑疑点 | 通常应为空；若非空看“问题解释(中文)” |
| `7_解析异常` | 表头乱码/字段混入等 | 重点看“检查列疑似混入决策内容”等 |

## 3) 两个最常用指标如何手算（对照 `4_检查-轮次明细`）

### 3.1 检查匹配率(严格)

- **D1 检查匹配率(严格)** = `D1分子_已执行匹配数合计 / D1分母_AI请求检查数`
  - 分母/分子在 `2_病例-检查匹配` 已汇总。
  - 逐轮展开在 `4_检查-轮次明细`：筛选 `阶段=D1 门诊循环`，对 `AI请求检查数`、`匹配数(最终)`求和即可复算。
  - 若该阶段出现 **“裁判缺失/未评测”**（即 AI 有请求但裁判没有匹配结果），该病例的分子/匹配率会留空，并进入 `5_需要复核-检查匹配`（复核原因会写明）。

- **D2 检查匹配率(严格)** = `D2分子_已执行匹配数合计 / D2分母_AI请求检查数(总)`
  - D2 分子由两部分组成：`D2 入院检查(源自D1决策建议)` + `D2 入院循环`（见 `2_病例-检查匹配` 的分子A/分子B）。

### 3.2 无效循环率(0匹配)

- **D1 无效循环率(0匹配)** = `D1无效循环轮次(0匹配) / D1循环轮次总数(有请求)`
- **D2 无效循环率(0匹配)** = `D2无效循环轮次(0匹配) / D2循环轮次总数(有请求)`

这两项的分子/分母已在 `2_病例-无效循环` 列出；逐轮明细仍在 `4_检查-轮次明细`。
更推荐你直接看 `4_无效循环-逐轮明细`：它只保留循环阶段且有请求的轮次，并显式标注“是否0匹配 / 是否未评测”。

## 3.3 Gate 指标（避免“失败 vs 未评测”混淆）

`outputs/latest/summary/指标汇总_中心模型.csv` 里有两套 Gate：

- **Gate* 流程通过率(基于流程状态)**：由流程状态推断（不会把“未经过/未评测”当成失败）。
- **Gate* Judge通过率(继续评测)**：来自裁判表的 `是否继续评测` 字段（只统计有裁判数据的样本，因此配套给出“Judge样本数”）。

## 4) 你如何反馈“需要复核”的问题？

推荐方式（可被脚本自动回填）：编辑 `work/latest/overrides/检查匹配_逐轮修正.csv`：

- 找到对应行（按 `中心/模型/病例ID/阶段代码/轮次` 定位）
- 在 `修正_AI请求检查数 / 修正_匹配数 / 修正_未匹配数` 填你认可的数值（可以只填其中两项，未填的会自动推导）
- 把 `采用修正(0/1)` 设为 `1`
- 保存后重新跑一次 `python src/run_metrics.py --tag latest`
  - 本次运行真正应用了哪些修正，会记录在 `work/latest/overrides/检查匹配_逐轮修正_应用记录.csv`

备选方式（便于你浏览/备注）：在每个 `outputs/latest/<中心>/<模型>/审阅表.xlsx` 的 `5_需要复核-检查匹配` 里填写：

- `反馈_结论`：例如 `确认无误` / `计数有误` / `疑似额外匹配项污染` / `需要我来修正` 等
- `反馈_建议动作`：例如 `把AI请求数改为5; 匹配数改为2`（写清楚你认可的分子/分母）
- `反馈_备注`：补充原因（可引用具体检查项）

你在 overrides 里的修正会被后续指标计算与汇总自动回填，可复现你的修正口径。
