# 审阅与复算指南（v1）

本指南面向“人工审阅 + Excel 手算复核”，目标是：你打开最少的表，能看懂每个指标怎么算、分子/分母从哪里来、哪里需要人工介入。

> 约束：系统不会修改 `data/` 与 `docs/`；所有修正副本与中间产物只写在 `work/` 与 `outputs/`。

---

## 1) 你应该打开哪些文件？

### A. 每个中心×模型一份“审阅表”

路径示例：
- `outputs/<run_id>/<中心>/<模型>/审阅表.xlsx`

你主要看这里。

### B. 总览汇总

- `outputs/<run_id>/summary/总览.xlsx`

包含：
- `指标汇总_中心模型`：中心×模型的汇总指标（含 Gate 分数均值）
- `解析异常`：例如表头乱码（门žen检查）等
- `审阅表索引`：每个中心×模型的审阅表路径

## 2) `审阅表.xlsx` 的 Sheet 结构（如何看、如何手算）

### 0_说明
- 解释“检查召回率 vs 检查合理性(LLM)”的区别
- 告诉你主要看哪些 sheet

### 1_汇总(中心-模型)
用途：快速看该中心×模型整体表现（可做报告图表的源数据）

常见列（示例）：
- `D1检查召回率均值` / `D2检查召回率均值`
- `D1无效循环率(0匹配)均值`（当前为“0匹配轮次占比”的代理指标）
- `关口1通过率`、`关口2通过率`
- `关口1总分均值`、`D3总分均值`、`D4总分均值` 等

> 如果某些 Gate 分数为 `NaN`：通常表示该中心×模型在该阶段未评测/未产生裁判输出。

### 2_病例-流程状态
用途：专门解决你说的“某节点结束了，但后面全是未经过，看不出终止点”的问题。

特点：
- 会把终止原因传播到后续阶段：例如 `未经过（流程终止于入院决策）`
- 你可以快速检查：终止点是否一致、有没有出现“loop 未经过但后面有环节却被写成终止/顺利通过”的异常

### 2_病例-检查召回
用途：**手算复核**（分子/分母拆开写清楚）

字段解释：
- `D1分母_GT门诊有效检查数`：GT 门诊检查里“有结果”的条目数（当前口径已确认，不涉及“合理性”）
- `D1分子_匹配检查数合计`：来自 `4_检查-轮次明细` 中 `阶段=D1 门诊循环` 的 `匹配数(最终)` 求和
- `D1检查召回率(相对GT有效检查)`：`D1分子 / D1分母`

D2 同理：
- `D2分子A_D1决策建议(匹配数)` + `D2分子B_入院循环(匹配数)` = `D2分子_匹配检查数合计(A+B)`
- `D2分母_GT有效检查数(按规则)`：默认用 `GT_Admission_Checks` 的有效数；若 D1 loop 未经过，按规则切换为 `(GT门诊有效 + GT入院有效)`（避免“用门诊+入院一起匹配”导致分母偏小）

### 3_病例-裁判评分
用途：把关口（Gate）的核心分数压缩成可读列（按 关口1/关口2/D3/D4 分组）

你可以：
- 过滤 `关口2_是否继续评测=0` 看失败病例
- 对比 `关口1_检查匹配度(0-1)` 与 `2_病例-检查召回` 的召回率是否一致（不一致一般来自“匹配列表污染/字段缺失”）

### 4_检查-轮次明细
用途：分子来源明细（**每轮一行**，可追溯）

核心列：
- `阶段`（中文）
- `轮次`
- `AI请求检查数`
- `匹配数(最终)`、`未匹配数(最终)`
- `匹配数来源(解释)`：说明为什么这个匹配数可信（优先锚定 AI 请求的未执行/未匹配列表）
- `未匹配检查(判官-未执行列表)`、`匹配检查(判官列表)`：用于人工核对（避免“判官把 AI 没提的血常规写进匹配列表”）

### 5_需要复核-检查匹配
用途：只列出“疑似有问题”的轮次（不是让你通读所有轮次）

你需要做什么：
- 在列 `反馈_结论 / 反馈_建议动作 / 反馈_备注` 填写你的判断

推荐填写口径（可自由）：
- `反馈_结论`：OK / 有问题 / 不确定
- `反馈_建议动作`：重跑LLM / 人工确认匹配数 / 判官匹配列表污染 / 数据字段异常
- `反馈_备注`：写明原因（例如“AI未提血常规，但判官匹配列表包含血常规”）

反馈导出（可选）：
- 你填完后可运行：`python src/run_collect_feedback.py --review-xlsx "<审阅表路径>"`  
  会生成 `<审阅表>.feedback.csv`，方便你直接发我或作为后续自动化的输入。

### 6_需要复核-状态逻辑
用途：列出自动检测到的流程状态疑点（如果为空，表示未检测到显著矛盾，但仍建议抽查 `2_病例-流程状态`）。

### 7_解析异常
用途：记录已发现的数据质量异常（例如表头乱码 `门žen检查`）。  
当前策略：**不改 data**，在内存里做“列名规范化 + 去重”，并在此表留痕。

## 3) “检查召回率”和“检查合理性(LLM)”的关系（避免混淆）

- **检查召回率（算法/半结构化）**：衡量“匹配到 GT 有效检查”的覆盖程度。  
  依赖：判官在自动评测中输出的“匹配/未执行”结构化字段（已包含语义匹配结果）。

- **检查合理性（LLM 指标）**：衡量“未匹配的检查是否仍有临床意义/是否冗余”。  
  依赖：`work/<run_id>/llm_tasks/llm.unmatched_check_reasonableness.jsonl` 的任务 + `src/run_llm_tasks.py` 执行结果。

二者不同：召回率不等于合理性；召回率低并不必然差（可能 GT 未做但 AI 提的合理）。
